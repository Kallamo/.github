# Security policy

This policy applies to every Kallamo project that does not have its own
`SECURITY.md`. A project's own policy, where there is one, takes precedence.

## Reporting a vulnerability

Please report security vulnerabilities privately, by e-mail to
**security@kallamo.com**. Do not open a public issue, pull request or Discord
message for a vulnerability until it is fixed.

Include, as far as you can:

- the affected project, component and version;
- a description of the issue and its impact;
- the steps or files needed to reproduce it;
- any suggested fix.

## What to expect

Kallamo projects are maintained by a small team, so these are targets, not
guarantees:

- an acknowledgement within 7 days;
- an assessment and, if the report is confirmed, a plan for a fix within 30
  days;
- a coordinated disclosure: the fix is released first, then the issue is
  published with credit to the reporter, unless you prefer to stay anonymous.

## Supported versions

Security fixes are released for the latest version of each project. Upgrade
to receive them.

## Scope

In scope: the code in Kallamo repositories and the packages and release
artifacts Kallamo publishes.

Out of scope: vulnerabilities in third-party services or dependencies that
Kallamo does not control (report those to their maintainers), and attacks
that require already controlling the user's machine or account.
